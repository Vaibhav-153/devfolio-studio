Three checks that must be real, not simulated.

  1. 01Cross-user privacy
    Test two real staging identities and private asset access.
  2. 02Live publishing
    Visit an actual portfolio on a wildcard HTTPS subdomain.
  3. 03Recovery
    Restore a previous release and a staging database backup.

Guided setup

Move from local source to staging

1. Create the private repository

Run the Next.js app checks in an environment with Node 22 and registry access. Generate a real dependency lockfile.

npm install
npm ci
npm run verify:phase6
npm run lint
npm run typecheck
npm run build

2. Create a disposable Supabase staging project

Apply all five database migrations. Configure email verification, redirects and service variables privately.

npx supabase login
npx supabase link --project-ref YOUR_STAGING_PROJECT_REF
npx supabase db push
npm run preflight:staging

3. Deploy staging and probe public routes

Connect your repository to Vercel, configure a staging domain, and run the read-only probe.

DEVFOLIO_PROBE_URL=https://your-staging-domain.com/ \
node scripts/release-smoke.mjs

4. Test real account isolation

Only in disposable staging, run the explicitly guarded script. It creates and attempts to clean up two synthetic users.

DEVFOLIO_TEST_ENV=staging \
STAGING_TEST_CONFIRM=CREATE_AND_DELETE_TEST_USERS \
STAGING_SUPABASE_PROJECT_REF=YOUR_STAGING_PROJECT_REF \
node scripts/staging-smoke.mjs
